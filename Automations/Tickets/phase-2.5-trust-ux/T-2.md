# T-2 Primer: Per-Run Outcome Card UI

**Project:** OpenHuman — Workflows & Automations / Phase 2.5 Trust UX
**Dependencies:** T-1 shipped (need `DeliveryReceipt` persisted + exposed via RPC).

---

## What Is This Ticket?

Replace the current "Succeeded — [agent narrative blob]" rendering on the run detail page with a structured **outcome card** that lists every concrete side effect the run produced, plus tool-call summary, plus the agent's narrative (still useful as context but no longer the headline). Render T-1's `DeliveryReceipt` rows as plain-English lines with provider-specific icons and **deep links** to the artifact (Gmail message, Slack message, Notion page, etc.).

### Why It Matters

The user's debugging pain comes from one place: the run-detail view tells them *what the agent said it did*, not *what actually happened*. T-2 is the first ticket the user *sees*. T-1 is invisible without it.

After T-2, the loop is:

> click Run → wait → see "✅ Sent email to alediez2408@gmail.com — Subject: Morning brief 6/7  [Open in Gmail]" → close laptop.

vs. today:

> click Run → wait → see "Succeeded — Email sent successfully. Here's the summary..." → don't believe it → open Gmail manually → search → find the email (hopefully).

---

## Implementation outline

### 1. Extend the RPC contract

`src/openhuman/workflows/schemas.rs` — the `workflows_get_run` response already returns `RunStep`. After T-1 lands, `RunStep.delivery_receipts: Vec<DeliveryReceipt>` is on the wire automatically. Add to the response shape:

- `cost_usd: f64` — sum across all `tool_calls` (each `ToolCallObservation` already has the elapsed/cost; thread the cost field through if not already)
- `failure_reason: Option<FailureReason>` — populated by T-4; T-2 ships with a `None` default and unfailing renderer

No new RPC method; extend `workflows_get_run`'s `RpcOutcome` payload.

### 2. Build the React component

`app/src/components/workflows/RunOutcomeCard.tsx` — props are the `RunStep[]` for the run plus the `Run` envelope (status, started_at, completed_at). Render:

- **Header line:** status icon + relative time + total cost + total tool-call count
- **Side-effects section:** map `step.delivery_receipts[]` → `<ReceiptRow icon={iconFor(kind)} ...>`; one row per receipt. If the run has zero receipts AND status is Succeeded AND `allowed_connections.length > 0`, show a warning subtitle: *"This run completed but produced no observable side effects."* (This case shouldn't happen after F-21; the subtitle is the belt for the suspenders.)
- **Read summary:** aggregate `tool_calls[]` by tool slug, show count + tool name in muted style ("📬 Read 7 unread Gmail messages" derived from `GMAIL_FETCH_EMAILS` × 1 with the `count` from the response).
- **Failure section** (when status is Failed): render `failure_reason` (T-4) if present, otherwise fall back to the existing `step.error` string with a `❌ ` prefix.
- **Agent narrative:** collapsed by default behind a `▸ Agent's notes (1 line, click to expand)` disclosure. The narrative is no longer the headline.

Sub-components:
- `<ReceiptRow icon, primary, secondary, link?>` — generic row
- `<ProviderIcon kind>` — maps `SideEffectKind` to emoji or SVG (start with emoji for speed)
- `<DeepLinkButton url, label>` — opens in default browser via Tauri shell

### 3. Wire into the run detail page

`app/src/pages/Workflows/RunDetail.tsx` — TODAY does not exist as a dedicated route (run detail is rendered inline in `WorkflowsList` overflow). Either:

- (preferred) create a proper route `/workflows/:wfid/runs/:runid` with `RunOutcomeCard` as the main content, plus a "Past runs" sidebar
- (lighter) render `RunOutcomeCard` inside the existing inline modal/drawer

Decide based on existing nav patterns; the lighter option lands faster and keeps T-2 focused on the card itself. Defer the proper route to T-2 follow-up if scope is tight.

### 4. i18n

Every string in `RunOutcomeCard` goes through `useT()` per CLAUDE.md i18n rule. Keys land in `app/src/lib/i18n/en.ts` and the corresponding chunk file (`en-N.ts` + every locale's `<locale>-N.ts`). Skipping this fails the i18n coverage gate.

Suggested key namespace: `workflows.outcome.*` (e.g. `workflows.outcome.sent_email`, `workflows.outcome.read_calendar_events`).
