# F4-12 Primer: Campaign Detail View

**Project:** OpenHuman — Workflows & Automations / Phase 4 Campaigns
**Dependencies:** F4-3 (RPC), F4-11 (list view).

---

## What Is This Ticket?

The structured detail view at `/campaigns/:id`. This is where the user inspects, edits, debugs, and converses with a campaign. The Linear-issue analog for OpenHuman campaigns.

### Why It Matters

The user's explicit ask from the 2026-05-26 grill:
> *"I want to be able to edit workflows from the workflows tab, connect new apps if I wanted to and even ask to update the workflow straight from the workflow view."*

The detail view is where (D)-hybrid editing, (i) modal connections, and (y) pinned chat all surface.

---

## Goal

Layout (three columns at desktop, stacked sections on narrow):

**Header strip (top):**
- Campaign name (click-to-edit, F4-13).
- Status pill + Pause/Resume button.
- "Discuss this campaign" button → opens chat with pinned context (F4-16).
- Overflow: Archive, Delete, Duplicate.

**Main column (center, 60% width):**
- **Overview section** — description, entity binding (`Attio: People (workspace abc)` with "Switch source" link), approval policy, throttle.
- **Sub-workflows section** — collapsible list, one expandable card per child workflow:
    - Trigger summary
    - Per-node-kind structured renderer (F4-14 wires this)
    - Run history mini-feed
    - "Edit this workflow" → expands inline form OR chat-update affordance
- **Entity preview** — first 10 records from the bound store with current status column. "See all" link → opens the external store in a new tab.
- **Approval queue badge** — if any pending drafts: link to `/approvals?campaign=<id>`.

**Right sidebar (30% width, collapsible):**
- **Activity feed** — chronological event stream: runs started/completed, approvals decided, throttle pauses, status transitions.
- **Connections panel** — list of integrations the campaign uses. Each has a "live" / "missing" indicator. Missing ones get a "Connect" button (F4-15 launches the modal).
- **Pinned-chat affordance** — small "Open chat" button that re-launches with workflow/campaign context (F4-16).

**Bottom strip:**
- Cost-to-date (when billing integrates).
- "Created from chat on YYYY-MM-DD" provenance.

Rendering invariants:
- Structured rendering MUST round-trip — what the user sees mirrors the persisted JSON exactly. No lossy "summarisation" of the campaign state.
- Sub-workflows render as collapsible cards, not free-form prose. The list is the structure.
- Entity preview is read-only in this view. Edits to the bound store happen in the bound store itself (Sheets / Attio).

RPC surface:
- `campaigns_get(id)` returns the campaign + sub-workflow list.
- `campaigns_throttle_status(id)` for the throttle counter.
- `workflows_list_runs(workflow_id)` for the per-sub-workflow mini-feed.
- `approvals_list_pending(campaign_id)` for the badge.
