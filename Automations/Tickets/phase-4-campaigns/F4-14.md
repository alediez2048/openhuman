# F4-14 Primer: Per-Node-Kind Form Editors

**Project:** OpenHuman — Workflows & Automations / Phase 4 Campaigns
**Dependencies:** F4-13 (inline edit primitives).

---

## What Is This Ticket?

A dedicated structured editor per Phase 2 `NodeKind`. Lets the user see and edit a node's full config inline in the campaign detail view — discoverable, validated, no LLM cost for the trivial parts.

### Why It Matters

A workflow node is more than its name — it has typed config (`HttpRequestConfig`, `ConditionConfig`, etc.). Generic text editing doesn't surface the structure. A per-kind editor makes the user fluent in what each node does AND prevents schema-drift errors.

---

## Goal

One editor component per Phase 2 node kind:

### `AgentPromptEditor.tsx`
- `prompt` — multi-line textarea (NON-trivial; clicking expands → chat panel for rewrites per F4-16).
- `allowed_connections` — chip selector showing live connections; clicking + opens connection modal (F4-15).
- `iteration_cap` — number input ∈ [1, 30] inline-edit.
- `model_tier` — dropdown: default / fast / medium / reasoning.

### `ToolCallEditor.tsx`
- `tool_name` — dropdown from the agent's tool registry (live-fetched).
- `arguments_template` — JSON editor with field-by-field rendering when the tool has a known schema; falls back to raw JSON otherwise. Templating tokens (`{{node.*.output}}`, `{{trigger.*}}`, `{{record.*}}`) auto-complete inside string leaves.

### `HttpRequestEditor.tsx`
- `connection_id` — generic-HTTP connection dropdown.
- `method` — radio (GET/POST/PUT/DELETE).
- `path_template` — text input + template-aware autocomplete.
- `headers` — key-value pair list with add/remove rows.
- `body_template` — textarea (NON-trivial → chat for big rewrites).
- `response_capture` — radio: body_and_status / status_only / json_path; json_path shows a path input when selected.

### `ChannelMessageEditor.tsx`
- `connection_id` — channel connection dropdown.
- `channel_id` — secondary dropdown populated from the chosen connection (or "default channel" when omitted).
- `body_template` — textarea (NON-trivial → chat).

### `ConditionEditor.tsx`
- `left` — text input with template autocomplete.
- `op` — dropdown: eq / not_eq / contains / matches.
- `right` — text input.
- `then_node_id` / `else_node_id` — dropdowns populated from the workflow's node list.
- Live evaluation preview: when the user types `{{node.classify.output.text}}` and the last run produced "urgent", show `left = "urgent"` so the user can sanity-check.

### `DelayEditor.tsx`
- `seconds` — number input + human-friendly secondary display ("1h 30m").

### `ForEachEditor.tsx` (new in F4-7)
- `entity_binding` — read-only (inherited from campaign).
- `query` — `EntityFilter` builder (field dropdown + op dropdown + value input rows).
- `body_nodes` — reorderable list of node ids in the workflow.
- `per_iteration_delay_secs` — number input.
- `max_per_run` — number input ∈ [1, 1000].

Cross-cutting UX:
- Each editor renders inside the sub-workflow card on the campaign detail view.
- Toggle: "Visual editor" (this one) vs "JSON view" (raw JSON for power users).
- Validation: errors surface inline next to the offending field, not as a blocking modal.
- Templating tokens highlighted in a different color in any text input that accepts them.
- "What does this do?" tooltip per field, pulled from the node-kind's docstring.

### Deliverables

- [ ] 7 editor components (one per Phase 2 kind + `ForEach`).
- [ ] Shared `EditorShell.tsx` wrapper providing the JSON-view toggle and per-field error display.
- [ ] Template autocomplete component (`TemplateInput.tsx`) used by every editor that accepts template strings.
- [ ] Connection / channel / tool dropdowns with live fetching.
- [ ] Live evaluation preview for `ConditionEditor` (reads last run's outputs).

### Tests

- Each editor renders correctly for a valid config.
- Each editor surfaces a validation error for an invalid config (e.g., `max_attempts = 10`).
- JSON-view toggle preserves the in-progress edit.
- Template autocomplete suggests `{{node.<id>.output}}` and `{{trigger.*}}` correctly.
