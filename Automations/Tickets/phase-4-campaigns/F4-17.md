# F4-17 Primer: Catalog Starter Campaigns RU-10..RU-12

**Project:** OpenHuman — Workflows & Automations / Phase 4 Campaigns
**Dependencies:** F4-1..F4-9 (campaigns runtime); F4-10 (drafter aware of campaigns); F4-12 (detail view can render them).

---

## What Is This Ticket?

Three new starter templates demonstrating the campaign shape end-to-end. These are the catalog equivalent of Phase 2's RU-5..RU-9 — they're the first thing a new user sees on `/campaigns` if they haven't created any themselves.

### Why It Matters

The three grill examples need to ship as starter templates so a new user can experience the full campaign flow with one click: pick template → connect adapters → click Run.

---

## Goal

Three new templates under `src/openhuman/workflows/templates/` (or a new `campaign-templates/` subdir):

### RU-10 — Vendor Outreach (the grill's primary example)

- **Entity binding:** Attio People (default; falls back to Google Sheet on adapter selection).
- **Throttle:** 20 / day.
- **Approval policy:** draft_and_approve.
- **Sub-workflows:**
    1. **Outbound batch** — Cron `0 9 * * *`. `for_each` over Attio People where `status = "uncontacted"` → agent_prompt (draft personalised email) + channel_message (Twilio SMS) → write status=`contacted` back to Attio.
    2. **Reply handler** — Composio event GMAIL_NEW_GMAIL_MESSAGE. Classify reply → if interested, draft follow-up + enqueue for approval; otherwise update Attio status to `not_interested`.
    3. **Daily digest** — Cron `0 17 * * *`. Read campaign throttle state + approval queue + Attio status counts → compose daily digest email → send to user.

### RU-11 — Content Calendar

- **Entity binding:** Google Sheets (content backlog with columns: title, draft, scheduled_at, posted, channel).
- **Throttle:** 1 post / day.
- **Approval policy:** draft_and_approve.
- **Sub-workflows:**
    1. **Generate batch** — Manual trigger. agent_prompt (read business context from memory → propose 30 content briefs → write to sheet).
    2. **Daily post** — Cron `0 10 * * *`. `for_each` over sheet rows where `posted = false AND scheduled_at <= today` → channel_message (Twitter / LinkedIn / etc.) → mark `posted = true`.
    3. **Engagement digest** — Cron `0 18 * * *`. Pull engagement metrics → email summary.

### RU-12 — Ads Performance Monitor

- **Entity binding:** Google Sheets (campaign list with columns: campaign_id, platform, daily_budget, status).
- **Throttle:** N/A (read-only campaign).
- **Approval policy:** triage (Mode C — deferred to Phase 5, so this template uses `draft_and_approve` as the MVP fallback with a note in the template that triage mode unlocks later).
- **Sub-workflows:**
    1. **Daily monitor** — Cron `0 8 * * *`. `for_each` over sheet rows → http_request to Google Ads / Meta Ads / etc. → write performance back to sheet.
    2. **Daily report** — Cron `0 9 * * *`. Read sheet → compose report → channel_message (Slack or email).

Each template JSON includes:
- `template_id`: ru-10-vendor-outreach / ru-11-content-calendar / ru-12-ads-monitor.
- `min_phase`: 4.
- `entity_binding_options`: list of compatible adapters (e.g., RU-10 accepts Attio OR Sheets).
- Rationale bullets explaining the architecture decisions.
- `required_connections`: explicit list per adapter combo.

Catalog UI changes:
- `/campaigns` list view's empty state surfaces the three new templates as cards.
- "Add" flow: user picks template → adapter selection sheet → drafts a CampaignProposal → preview → Save.
