# F4-3 Primer: Campaign CRUD Ops + RPC + Agent Propose Tools

**Project:** OpenHuman — Workflows & Automations / Phase 4 Campaigns
**Dependencies:** F4-1 (types), F4-2 (store).

---

## What Is This Ticket?

The operational + RPC + agent-tool surface for Campaigns. Mirrors what `workflows/ops.rs` + `workflows/rpc.rs` + `workflows/schemas.rs` did for workflows in Phase 1.

### Why It Matters

The chat-driven creation flow needs `campaign_propose_create` to draft new campaigns. The detail-view UI needs `campaigns_list`, `campaigns_get`, `campaigns_pause`, etc. The drafter agent needs the propose tools added to its allowlist.

## Goal

`src/openhuman/campaigns/ops.rs`:

- `pub async fn create(config, CreateCampaignRequest) -> RpcOutcome<Campaign>`
- `pub async fn get(config, CampaignId) -> RpcOutcome<Option<Campaign>>`
- `pub async fn list(config, ListFilter) -> RpcOutcome<Vec<Campaign>>`
- `pub async fn update(config, UpdateCampaignRequest) -> RpcOutcome<Campaign>`
- `pub async fn delete(config, CampaignId) -> RpcOutcome<bool>` (soft-delete)
- `pub async fn restore(config, CampaignId) -> RpcOutcome<Option<Campaign>>`
- `pub async fn pause(config, CampaignId) -> RpcOutcome<Campaign>` — flips status `Active` → `Paused`, pauses all sub-workflows.
- `pub async fn resume(config, CampaignId) -> RpcOutcome<Campaign>` — flips back to `Active`, re-enables sub-workflows.
- `pub async fn archive(config, CampaignId) -> RpcOutcome<Campaign>` — terminal state; sub-workflows disabled.
- `pub async fn add_workflow(config, CampaignId, WorkflowId) -> RpcOutcome<bool>` — links existing workflow to campaign.
- `pub async fn remove_workflow(config, CampaignId, WorkflowId) -> RpcOutcome<bool>` — unlinks (sets `workflows.campaign_id = NULL`).

Agent propose tools (read-only + propose pattern from F-12):

- `campaign_list` — read-only, lists campaigns (parallel to `workflow_list`).
- `campaign_get` — read-only.
- `campaign_propose_create` — drafts a `CampaignProposal` via the sub-agent.
- `campaign_propose_update` — drafts an `EditCampaignProposal` against a current row.
- `campaign_propose_pause` / `_resume` / `_archive` — `CampaignStateProposal` shape.

All propose tools live under `src/openhuman/tools/impl/campaigns/`.

`CampaignProposal` shape mirrors `WorkflowProposal`:

```rust
struct CampaignProposal {
    name: String,
    description: String,
    entity_binding: EntityRef,
    throttle: Option<Throttle>,
    approval_policy: ApprovalPolicy,
    target_outcome: Option<OutcomeSpec>,
    proposed_workflows: Vec<WorkflowProposal>, // sub-workflows to create alongside
    rationale: Vec<String>,
    required_connections: Vec<ConnectionRef>,
    missing_connections: Vec<ConnectionRef>,
    setup_instructions: Option<String>,
    confidence: Confidence,
}
```

Lifecycle invariants (enforced in `ops.rs`):

- `Draft → Active | Archived`
- `Active → Paused | WoundDown | Archived`
- `Paused → Active | Archived`
- `WoundDown → Archived` (terminal-ish)
- `Archived` — terminal, no transitions.

Pausing a campaign **must** disable every child workflow (calls `workflows::ops::disable` for each `campaign_id = self`). Resuming re-enables.

### Deliverables

- [ ] `campaigns/ops.rs` with the 11 operations above.
- [ ] `campaigns/rpc.rs` + `schemas.rs` with the 9 JSON-RPC controllers.
- [ ] `tools/impl/campaigns/{list,get,propose_create,propose_update,propose_pause,propose_resume,propose_archive}.rs` (7 agent tools).
- [ ] Orchestrator allowlist update — add `campaign_*` tools to `agent/agents/orchestrator/agent.toml` (per the memory: `feedback_orchestrator_allowlist`).
- [ ] `DomainEvent` variants: `CampaignDefined`, `CampaignUpdated`, `CampaignPaused`, `CampaignResumed`, `CampaignArchived`, `CampaignDeleted`.

### Tests

- Lifecycle transitions: every valid transition succeeds, every invalid one fails with a clear `InvalidCampaignTransition` error.
- `pause` disables all child workflows; `resume` re-enables; idempotent on re-call.
- `delete` soft-deletes; `restore` brings it back.
- Adding/removing workflows updates `workflows.campaign_id` correctly.
- Agent tool round-trip: drafting + apply → real DB row.
