# F4-8 Primer: Campaign Throttle Primitive

**Project:** OpenHuman — Workflows & Automations / Phase 4 Campaigns
**Dependencies:** F4-3 (Campaign type with `throttle`), F4-7 (`for_each` consumes the throttle budget).

---

## What Is This Ticket?

Runtime enforcement of `Campaign.throttle` — "20 per day" across all sub-workflows and all `for_each` iterations. Persistent budget across runs.

### Why It Matters

The user's vendor-outreach example: "20 vendors per day for the next month." Without a campaign-level throttle, the workflow would either send all 600 at once or rely on the LLM to count, which is unreliable. The throttle is a deterministic gate the executor enforces.

## Goal

New SQLite table `campaign_throttle_state`:

```sql
CREATE TABLE IF NOT EXISTS campaign_throttle_state (
    campaign_id   TEXT NOT NULL,
    window_start  TEXT NOT NULL,  -- ISO-8601, the bucket boundary
    consumed      INTEGER NOT NULL DEFAULT 0,
    PRIMARY KEY (campaign_id, window_start)
);
```

Migration 007 lands this.

`src/openhuman/campaigns/throttle.rs`:

```rust
pub struct ThrottleGate;

impl ThrottleGate {
    /// Reserve `n` units of throttle budget for `campaign_id`. Returns
    /// the actual reservation count (may be less than `n` if the budget
    /// is partially full). `Ok(0)` means fully exhausted for this window.
    pub fn reserve(
        config: &Config,
        campaign_id: &CampaignId,
        n: u32,
    ) -> Result<u32>;

    /// Release a previously-reserved unit (e.g. iteration failed before
    /// the externally-visible action — we shouldn't count it).
    pub fn release(
        config: &Config,
        campaign_id: &CampaignId,
        n: u32,
    ) -> Result<()>;

    /// Current consumption for the active window.
    pub fn current(
        config: &Config,
        campaign_id: &CampaignId,
    ) -> Result<ThrottleSnapshot>;
}

pub struct ThrottleSnapshot {
    pub window_start: DateTime<Utc>,
    pub window: ThrottleWindow,
    pub consumed: u32,
    pub limit: u32,
    pub remaining: u32,
}
```

`for_each` node body integration (F4-7 extends):
- Before each iteration, call `ThrottleGate::reserve(campaign_id, 1)`.
- If `Ok(0)`, pause the for_each iteration:
    - If `Throttle::PerDay`: schedule a continuation for tomorrow at the same time (uses F2-7b's `pending_resume_at` infrastructure).
    - If `Throttle::PerHour`/`PerMinute`: in-process sleep (short windows).
- If `Ok(1)`, proceed with the iteration.
- On iteration failure BEFORE the externally-visible action (e.g. validation error pre-send), call `release(1)`.
- On iteration success or post-action failure, keep the reservation.

Window boundary semantics:
- `PerDay`: midnight UTC.
- `PerHour`: top of the hour.
- `PerMinute`: top of the minute.

User-facing copy when the throttle pauses a run: `WorkflowRunSkipped { reason: throttle_exhausted, campaign_id, window_start, next_window_at }`.
