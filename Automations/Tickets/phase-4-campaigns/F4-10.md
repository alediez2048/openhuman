# F4-10 Primer: Campaign-Aware Drafter Prompt

**Project:** OpenHuman — Workflows & Automations / Phase 4 Campaigns
**Dependencies:** F4-3 (`CampaignProposal` shape, propose tools).

---

## What Is This Ticket?

Rewrite of the workflow_builder drafter prompt so the LLM recognises campaign-shaped intent vs single-workflow intent, negotiates entity schemas mid-chat, and proposes multi-workflow campaigns when appropriate.

### Why It Matters

The drafter today only emits `WorkflowProposal`. After Phase 4 it must ALSO emit `CampaignProposal` when the user describes a campaign-shaped flow. Without the prompt rewrite, the user says *"vendor outreach to 1000 contacts"* and gets back a single agent_prompt node again.

---

## Goal

Update both copies (per F-13 dual-write convention):
- `Automations/Artifacts/prompts/workflow_builder.md` (design-time SoT)
- `src/openhuman/agent/prompts/workflow_builder.md` (bundled, byte-identical)

New sections:

1. **Campaign vs Workflow — when to use which.**
   Decision tree for the LLM:
   - "Long-running stateful process over N records" → campaign.
   - "One-shot reactive trigger" → workflow.
   - "Multi-channel touching shared state" → campaign.
   - Ambiguous → ask the user.

2. **Campaign shape reference.**
   `CampaignProposal` JSON shape (mirrors the F2-13 workflow reference). Includes `entity_binding`, `throttle`, `approval_policy`, `target_outcome`, `proposed_workflows`.

3. **Entity schema negotiation flow.**
   When the user says *"vendors in this sheet"*, the drafter MUST:
   - Call `entity_schema_inspect(EntityRef::GoogleSheet { spreadsheet_id, range })` to fetch the schema.
   - Present the inferred fields to the user inline ("I see columns: email, name, last_contacted, status — does `status` track replies?").
   - Confirm before proposing the campaign.

4. **Default policies.**
   - `ApprovalPolicy::DraftAndApprove` is the MVP default (per the grill's Mode B lock).
   - `throttle: 20/day` is a sensible starting throttle for outreach; the LLM picks based on user's intent (smaller for high-value, larger for lower-touch).

5. **Worked example — vendor outreach campaign.**
   The user says: *"I want to email 1000 local vendors about my new service. Use Attio and Gmail. 20 per day."*
   The drafter emits a `CampaignProposal` with:
   - `entity_binding: { type: "attio", workspace_id: ..., object_type: "people" }`
   - `throttle: { max_per_window: 20, window: "per_day" }`
   - `approval_policy: { kind: "draft_and_approve" }`
   - 3 `proposed_workflows`: outbound batch (cron, `for_each` over vendor query), inbound reply (composio_event GMAIL_NEW_MESSAGE), daily digest (cron).
   - Rationale bullets explaining each choice.

6. **What NOT to propose.**
   - Single-workflow campaigns for one-shot triggers (use plain `WorkflowProposal`).
   - Campaigns without an `entity_binding` (the campaign abstraction is meaningless without a recordset).
   - `ApprovalPolicy::AutoReply` until the user explicitly opts in (the platform-default lock).
   - More than 5 `proposed_workflows` per campaign (smell — break into multiple campaigns).

`proposer.rs` updates:
- Phase constants bumped — `CURRENT_PHASE = 4`.
- `phase_constraints_block(4)` inlines campaign-aware constraints.
- New entity_schema_inspect agent tool (`entity_schema_inspect(entity_binding)`) so the drafter can fetch the schema mid-chat.
- New `CampaignAwareDrafter` trait — the existing `Drafter` returns `WorkflowProposal | CampaignProposal` as an enum.
