# F4-6 Primer: Attio Adapter

**Project:** OpenHuman — Workflows & Automations / Phase 4 Campaigns
**Dependencies:** F4-4 (`EntityStore` trait), F4-5 (proves trait against a real adapter).

---

## What Is This Ticket?

The second concrete `EntityStore` implementation — Attio as the CRM backing store. Typed records, real webhooks, stable record IDs. The demographic ask from the 2026-05-26 grill.

### Why It Matters

The user explicitly named Attio twice as their preferred CRM. Without this adapter, the headline campaign use case ("connect my Attio and run real campaigns") doesn't work at launch. Equally important: validates the trait against a typed schema source, complementing Sheets' untyped surface.

---

## Goal

`src/openhuman/campaigns/entity_store/attio.rs`:

- Authenticates via the existing Composio `ATTIO` integration.
- `schema()` returns the typed object schema from Attio's `GET /v2/objects/{object_type}/attributes` endpoint:
    - `people` → fields like `name`, `email_addresses`, `phone_numbers`, `job_title`, `companies`.
    - `companies` → `name`, `domains`, `team`, `categories`.
    - `deals` → `name`, `stage`, `value`, `owner`, `associated_people`.
- `list(query)` uses Attio's `POST /v2/objects/{object_type}/records/query` with proper server-side filter translation (Attio supports rich filtering — translate `EntityFilterOp::Eq` → `{"$eq": value}`, etc.).
- `get(&id)` calls `GET /v2/objects/{object_type}/records/{record_id}`.
- `update(&id, patch)` calls `PATCH /v2/objects/{object_type}/records/{record_id}` with the field map.
- `subscribe()` registers an Attio webhook (`POST /v2/webhooks`) pointing at a tunnel URL OpenHuman manages — when Attio fires a record-change event, it lands in OpenHuman as an `EntityChange`.
- Identity: `EntityId { adapter: "attio", native: record_id /* Attio's stable UUID */ }`.

Webhook lifecycle (F4-6 detail):
- Adapter creates the webhook on `subscribe()`, tears it down when the stream is dropped.
- The webhook URL is registered against the same tunnel infrastructure F2-9 built for `Trigger::Webhook`.
- HMAC verification against Attio's signing secret.

Schema example output for Attio People:

```json
{
  "primary_field": "record_id",
  "fields": [
    { "key": "name", "label": "Name", "kind": { "kind": "string" }, "required": true },
    { "key": "email_addresses", "label": "Email Addresses", "kind": { "kind": "string" }, "required": false },
    { "key": "phone_numbers", "label": "Phone Numbers", "kind": { "kind": "phone_number" }, "required": false },
    { "key": "job_title", "label": "Job Title", "kind": { "kind": "string" }, "required": false },
    { "key": "companies", "label": "Companies", "kind": { "kind": "string" }, "required": false }
  ]
}
```
