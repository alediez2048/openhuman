# F4-13 Primer: Inline Form Editor (Trivial Fields)

**Project:** OpenHuman — Workflows & Automations / Phase 4 Campaigns
**Dependencies:** F4-12 (detail view shell).

---

## What Is This Ticket?

Click-to-edit affordances on the trivial fields of the campaign + sub-workflow detail surface. Per the (D)-hybrid editor decision from the 2026-05-26 grill: trivial fields commit via direct RPC, no LLM round-trip.

### Why It Matters

Renaming a campaign or changing its cron expression shouldn't require chatting with an LLM. These are single-field changes the user already knows the answer to. Direct edit + optimistic UI is faster, cheaper, and matches user expectations from every other app they use.

---

## Goal

The split rule from the grill — does this edit need a draft preview before commit?
- **No → form.** Trivial knobs.
- **Yes → chat (F4-16 handles).** Reasoning edits.

Concrete trivial-field assignments:

| Field | Widget | Validation |
|---|---|---|
| Campaign name | Inline text input | non-empty, ≤120 chars |
| Campaign description | Inline textarea | optional, ≤2000 chars |
| Campaign status (Pause/Resume/Archive) | Header buttons | Lifecycle transitions enforced server-side (F4-3) |
| Throttle `max_per_window` | Inline number input | ∈ [1, 10000] |
| Throttle `window` | Dropdown | per_minute / per_hour / per_day |
| Approval policy kind | Dropdown | draft_and_approve / auto_reply / triage / tiered |
| Entity binding (whole `EntityRef`) | "Switch source" button → flow F4-15 | adapter-specific validation |
| Workflow name | Inline text input | non-empty |
| Workflow description | Inline textarea | optional |
| Workflow enabled toggle | Switch | bool |
| Settings.timeout_secs | Inline number input | ∈ [1, 3600] |
| Settings.on_error | Dropdown | halt / continue |
| Trigger.cron.expr | Inline cron picker | parses via `cron::Schedule` |
| Trigger.cron.tz | IANA tz dropdown | curated list |
| Trigger.active_hours.start/end | Time pickers | 00:00–23:59 |
| Node.config.connection_id | Connection dropdown | live connections from `/connections` |
| Node.config.channel_id | Channel dropdown | populated from selected connection |
| Node.retry_policy.max_attempts | Number input | ∈ [1, 5] |
| Node.retry_policy.backoff.initial_ms | Number input | ∈ [100, 10000] |
| Node.retry_policy.backoff.max_ms | Number input | ≤ 60000 |

NON-trivial (these route to F4-16 chat panel):
- Node prompt / body_template / arguments_template (anything prose-shaped).
- Adding / removing / reordering nodes.
- Changing trigger type.
- Changing `condition` node operands.
- Changing entity_binding to a different adapter.

UX semantics:
- Click field → input takes focus.
- Edit → Enter or click-out commits.
- Optimistic UI: change applies immediately, RPC fires in background.
- On RPC error: revert + toast.
- Saving spinner only when RPC > 500ms.
- Esc cancels in-progress edit.
- Form fields render with a subtle "click to edit" affordance (pencil icon on hover).

RPC surface:
- New atomic-patch RPC: `openhuman.campaigns_update_field(id, field_path, new_value)` for campaign-level edits.
- New atomic-patch RPC: `openhuman.workflows_update_field(id, field_path, new_value)` for workflow-level edits.
- Each enforces the validation table above on the server side; client UI mirrors validation for instant feedback.

### Tests

- Click → edit → Enter commits and re-renders.
- Invalid value (e.g., `max_attempts = 10`) is rejected client-side AND server-side.
- Optimistic UI flips back on RPC error + toast appears.
- Esc cancels without committing.
- Concurrent edits from two browser tabs converge correctly (last-writer-wins is acceptable for MVP).
