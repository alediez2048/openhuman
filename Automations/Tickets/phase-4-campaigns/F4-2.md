# F4-2 Primer: Campaigns Table + Migration 006

**Project:** OpenHuman — Workflows & Automations / Phase 4 Campaigns
**Dependencies:** F4-1 (types).

---

## What Is This Ticket?

The persistence layer for `Campaign`. Adds migration `006_campaigns.sql` to `workflows.db` (same DB — campaigns live alongside workflows per ADR-003's separate-DB rule), adds the foreign-key relationship from `workflows.campaign_id`, and lands `src/openhuman/campaigns/store.rs` with full CRUD parity to the workflows store.

### Why It Matters

Campaigns need persistent state. Lifecycle transitions (active → paused → wound-down) must survive core restarts. Sub-workflows reference their parent campaign by FK so cascade rules work cleanly.

---

## Goal

Migration `006_campaigns.sql`:

```sql
CREATE TABLE IF NOT EXISTS campaigns (
    id              TEXT PRIMARY KEY,
    schema_version  INTEGER NOT NULL DEFAULT 1,
    name            TEXT NOT NULL,
    description     TEXT,
    status          TEXT NOT NULL,
    entity_binding  TEXT NOT NULL,  -- JSON-encoded EntityRef
    throttle        TEXT,            -- JSON-encoded Throttle (nullable)
    approval_policy TEXT NOT NULL,   -- JSON-encoded ApprovalPolicy
    target_outcome  TEXT,            -- JSON-encoded OutcomeSpec (nullable)
    created_at      TEXT NOT NULL,
    updated_at      TEXT NOT NULL,
    last_run_at     TEXT,
    deleted_at      TEXT  -- F2-14 soft-delete pattern
);

CREATE INDEX idx_campaigns_status ON campaigns(status);
CREATE INDEX idx_campaigns_deleted_at ON campaigns(deleted_at);

ALTER TABLE workflows ADD COLUMN campaign_id TEXT REFERENCES campaigns(id) ON DELETE SET NULL;
CREATE INDEX idx_workflows_campaign_id ON workflows(campaign_id);
```

`src/openhuman/campaigns/store.rs` — full CRUD mirroring `workflows/store.rs`:

- `insert_campaign(config, &Campaign) -> Result<()>`
- `get_campaign(config, &id) -> Result<Option<Campaign>>`
- `list_campaigns(config, filter) -> Result<Vec<Campaign>>` — `status` filter, `include_deleted` toggle.
- `update_campaign(config, &Campaign) -> Result<bool>`
- `delete_campaign(config, &id) -> Result<bool>` — soft-delete, sets `deleted_at`.
- `restore_campaign(config, &id) -> Result<bool>` — clears `deleted_at`.
- `list_workflows_for_campaign(config, &id) -> Result<Vec<Workflow>>`

Cascade semantics: deleting a campaign **does NOT** cascade-delete child workflows. Instead `ON DELETE SET NULL` on `workflows.campaign_id` orphans them. Rationale: a campaign delete is a user mistake risk; we'd rather orphan workflows than lose them. The F2-14 retention sweep eventually purges archived campaigns + orphaned workflows separately.
