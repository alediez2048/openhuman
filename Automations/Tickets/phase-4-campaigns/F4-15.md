# F4-15 Primer: Connection Modal Launcher

**Project:** OpenHuman — Workflows & Automations / Phase 4 Campaigns
**Dependencies:** F4-12 (detail view), F4-14 (editors that surface "missing connection" affordances).

---

## What Is This Ticket?

A modal that launches the existing `/connections` flow from within the campaign detail view. Per the grill's (i) decision — modal launch, NOT inline-embedded cards and NOT deep-link navigation.

### Why It Matters

The user explicitly asked: *"connect new apps if I wanted to."* Today the only path to add a connection is to leave the campaign view and navigate to `/connections`. That breaks flow. A modal keeps the user "home" on the campaign while delegating the connection flow to its own well-tested surface.

---

## Goal

`app/src/components/connections/ConnectionLauncherModal.tsx`:

- Renders as a full-screen-on-mobile, centered-modal-on-desktop dialog.
- Embeds the existing `/connections` page content as the modal body — same React tree, same RPC calls, same auth flows.
- Header: "Connect [Adapter Name]" + close button.
- On successful connection: modal auto-closes + emits `onConnected(connectionRef)` callback. The caller refreshes its data.

Triggering surfaces:

1. **Sub-workflow card** detects a `connection_id = ""` or `connection_id = "PLACEHOLDER"` (starter-template placeholder) → renders a warning banner with "Connect [X]" button → launches the modal pre-filtered to the relevant adapter family.

2. **AgentPromptEditor's `allowed_connections` chip selector**: clicking the "+ Add" chip opens the modal with no pre-filter so the user can choose any adapter.

3. **EntityBinding "Switch source" button** in the campaign overview: opens the modal pre-filtered to entity-store-capable adapters (Sheets + Attio for MVP).

4. **ConnectionsPanel sidebar** (F4-12): every "missing" entry has a one-click launch.

Modal behavior:
- Backdrop click → confirms before close if mid-OAuth.
- Esc key → same confirmation if mid-flow.
- Successful OAuth flow → toast notification + modal closes.
- Failed flow → error displayed inside the modal; user can retry without losing context.

Routing:
- URL stays at `/campaigns/:id` during the modal — no route change.
- Deep-link to "open campaign detail with connection modal open" is supported via query param: `/campaigns/:id?connect=stripe`.

RPC integration:
- Modal calls the same `connections_*` RPCs the standalone page does.
- New event subscription: when the modal sees `DomainEvent::ConnectionAdded` matching what was requested, it auto-closes.

### Deliverables

- [ ] `components/connections/ConnectionLauncherModal.tsx` reusing the page-level connections component tree.
- [ ] Hook `useConnectionLauncher(filter?)` exposing `{ open, close, isOpen }` for trigger components.
- [ ] Trigger integrations in sub-workflow card, agent-prompt editor, entity-binding switch, connections panel sidebar.
- [ ] Query-param deep-link support.
- [ ] Toast on success/failure.
- [ ] In-flow exit confirmation.

### Tests

- Modal opens with the right adapter pre-filtered for each trigger surface.
- Successful connection auto-closes + emits callback.
- Backdrop click during OAuth shows confirmation.
- Query param `?connect=stripe` opens modal on initial render.
- Modal coexists cleanly with the chat sidebar (F4-16) — neither one steals focus.
