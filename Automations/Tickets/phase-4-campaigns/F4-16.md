# F4-16 Primer: Pinned Workflow Context in Global Chat

**Project:** OpenHuman — Workflows & Automations / Phase 4 Campaigns
**Dependencies:** F4-3 (`workflow_propose_update` already exists; this extends the chat surface).

---

## What Is This Ticket?

The chat-half of the (D)-hybrid editor. From the campaign / workflow detail view, the user clicks "Discuss this" → the main `/chat` opens with the workflow (or campaign) pinned as context. Every message in that conversation implicitly references the pinned object.

### Why It Matters

The user explicitly said: *"even ask to update the workflow straight from the workflow view."* For non-trivial edits (prompt rewrites, restructuring, adding nodes), the right surface is conversational. F4-16 makes that path frictionless: one click → chat opens → user says "make the email warmer" → drafter proposes the change → user clicks Apply.

---

## Goal

UI changes:

- **Header chip in `/chat`:** when chat is opened with a pinned context, a removable chip appears at the top of the chat: *"📋 Pinned: [Campaign Name] / [Workflow Name]"*. Clicking the X removes the pin and the chat reverts to normal.
- **Detail-view "Discuss this" button** (added in F4-12 / F4-13) navigates to `/chat?pin=campaign:<id>` or `/chat?pin=workflow:<id>`.
- **System prompt preamble injection:** when a context is pinned, the agent's system prompt gains a section: *"The user is currently editing campaign `<name>` (id: `<id>`). Recent runs, status, and configuration follow:..."* with a compact context snapshot.
- **Tool routing:** the propose tools (`workflow_propose_update`, `campaign_propose_update`) are auto-targeted at the pinned id when the user says *"change the schedule to 9am"* without specifying which workflow.

Pin state management:
- Stored in the URL query string (`?pin=campaign:abc-123`), survives reloads.
- Stored in the chat session so the system-prompt preamble is consistent across turns.
- Multiple pins not allowed for MVP (one pinned context at a time). If user opens a new pin, the old one drops with a small "Unpinned [previous]" toast.

System-prompt preamble shape (≤2 KiB to avoid bloating the chat prompt):

```
## Pinned context

You are helping the user with this campaign:

Name: Austin Pickleball Outreach
Status: Active (paused: false)
Entity binding: Attio People (workspace W123)
Throttle: 20/day
Approval policy: draft_and_approve
Sub-workflows: 3 (outbound-cron, reply-handler, daily-digest)
Recent runs (last 3):
- outbound-cron: 2026-05-26 09:00 — Succeeded (20 sends)
- outbound-cron: 2026-05-25 09:00 — Succeeded (20 sends)
- reply-handler: 2026-05-25 14:32 — Succeeded (1 reply drafted, queued for approval)

When the user asks for a change, prefer calling `campaign_propose_update` or
`workflow_propose_update` on the pinned id without re-asking which workflow.
```

The preamble is built by a new helper `build_pinned_context_preamble(config, pin_ref)` in the agent harness.

Auto-targeting heuristic:
- If pin is `campaign:<id>` and user says *"add a Slack notification"* → drafter targets the campaign + proposes a new sub-workflow.
- If pin is `workflow:<id>` and user says *"change the schedule to 9am"* → drafter targets the workflow + proposes an edit.
- If user explicitly names a DIFFERENT workflow in their message → drafter follows the explicit reference (heuristic loses).

Quick-action chips (shown above the chat input when pinned):
- "Pause this" → fires `campaign_propose_pause(id)`.
- "Add a step" → preloads chat with *"Add a step that…"* template.
- "Test run" → fires `workflows_run_now` on the pinned workflow (if it's a workflow pin).
