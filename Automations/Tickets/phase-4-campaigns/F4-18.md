## Goal

### Hero E2E spec — `app/test/e2e/specs/campaigns-phase-4-hero.spec.ts`

One Appium session walking the user-facing happy path:

1. Fresh workspace. Open `/campaigns` — empty state with 3 starter cards (RU-10..RU-12).
2. Click [Add] on RU-10 (vendor outreach) → adapter selection sheet → pick Google Sheets.
3. Chat opens with template prefilled → user adds *"sheet ID = 1RC..."* → drafter proposes a `CampaignProposal`.
4. `<CampaignProposalPreview>` renders with 3 sub-workflows + entity binding + throttle + approval policy.
5. Click [Save & Activate].
6. Campaign row appears in `/campaigns`. Click it → detail view renders.
7. Detail view sanity checks:
    - Header status pill = Active.
    - 3 sub-workflow cards visible.
    - Throttle counter shows "0 / 20 today."
    - Entity preview shows first 10 sheet rows.
    - Activity feed is empty (no runs yet).
8. Inline rename: change campaign name → optimistic UI flips → poll RPC confirms the new name.
9. "Discuss this" → chat opens with the campaign pinned. Send *"change throttle to 10 per day."* → drafter proposes an update → click Apply.
10. Detail view refreshes → throttle now reads "10."
11. Manually fire the outbound-batch sub-workflow via Run Now.
12. Wait for the run to land in the approval queue (`/approvals` shows N drafts).
13. Approve all drafts.
14. Workflow run succeeds; sheet rows have `status=contacted` written back.

Each step has a clear oracle assertion + meaningful failure message naming the step number.
